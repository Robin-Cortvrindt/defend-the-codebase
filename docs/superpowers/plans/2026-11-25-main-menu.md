# Main menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real title screen (menu, How to play, compact Investments) before a run, a Quit button during a run, and a way back to the menu after a game over.

**Architecture:** The screens stay as overlays in `#stage` (approach A). `#app[data-screen]` tells CSS what to hide: board, bars and HUD run items. The menu screens move to a new `src/engine/menu.js`. Quit ends the run through the existing loss path in `game.js`, so the payout and collapse animation are reused.

**Tech Stack:** Plain ES modules, DOM, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-25-main-menu-design.md`, mockup `docs/mockups/main-menu.html`.

## Global Constraints

- No "Intent Engineering Bootcamp" line on the menu.
- Quit pays like a loss (`game:lost` → `awardCapital`) and counts toward Best run.
- After a quit: the collapse plays, then the main menu (no "Production is down" card).
- Keyboard help appears only on How to play, never during runs.
- All 16 investments fit on one Investments screen at 1100px wide.

## Review Focus

- Space/Enter on the menu starts a run (today `onWaveButton` handles `menu`); it must not fire while the quit box is open.
- Esc while the quit box is open closes it and resumes, with no other side effects.
- Quit during the `review` or `bell` phase (not only `wave`): it must still collapse and pay out.
- Pressing Quit twice, or Quit during the collapse: no double payout (`awardCapital` is already idempotent via `game.capitalEarned`) and no second `game:lost`.
- Investments opened from the game-over screen: Back returns to the game-over card, not the menu.

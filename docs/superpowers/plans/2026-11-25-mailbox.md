# Mailbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An inbox of task mails that pay Warrants or a free Claude on Claim, where about 1 in 6 is phishing and punishes the claim instead.

**Architecture:** One feature file, `src/content/features/mailbox.js`, plus one manifest line. All logic is plain exported functions that operate on `game.mailbox`, tested in Node. Bus listeners at the top level forward events to those functions. The DOM layer (card badge, panel, toast, styles) is guarded by `typeof document !== 'undefined'` and checked by hand in the browser.

**Tech Stack:** Vanilla ES modules, `node:test`, canvas 2D for the padlock and red flash, DOM for the panel and toast.

**Spec:** `docs/superpowers/specs/2026-11-25-mailbox-design.md`. Mockups: `docs/mockups/mailbox.html`.

## Global Constraints

- No edits under `src/engine/`. Only `src/content/features/mailbox.js`, one line in `src/content/manifest.js`, a test file, and a README line.
- Bus listeners use `on(...)` at the top level of the file, never inside `init`.
- Constants: `MAX_MAILS = 4`, `FIRST_MAIL_DELAY = 5`, `MAIL_INTERVAL = 30` (seconds of scaled game time), `PHISH_CHANCE = 1/6`, `CLAUDE_REWARD_CHANCE = 1/8`, `CLAUDE_STEAL = 100`, `LOCK_SECONDS = 10`, malware count `Math.min(8, 3 + Math.floor(game.sprint / 3))`.
- The game is now endless sprints. The index is `game.sprint`, with `game.wave` kept as an alias. Player-facing text says "sprint", never "wave".
- Every random choice goes through `game.random`.
- The mail timer only runs in the `building`, `wave` and `bell` phases. In `review` (the quarter review screen) the timer pauses and the panel and toast are hidden.
- Copy follows the house style: Nexios palette, Lato, sentence case, no emoji, no exclamation marks. Real and phishing mails look identical everywhere until claimed.
- Senders are roles: HR, Training manager, Business manager, CEO, IT service desk.
- `node --test` must stay green, including `tests/content.test.js`, which loads the whole manifest in Node.

## Review Focus

1. **Restart mid-game:** `init` gives fresh mailbox state. That means no leftover mails, vouchers, locks or queued malware, and no doubled listeners. Pinned in Task 1.
2. **Double claim:** a second claim of the same mail returns `null` and changes nothing. Pinned in Task 2.
3. **Surviving across a quarter review:** "Survive 2 more sprints" counts `sprint:cleared`. That event also fires for the last sprint of a quarter, just before the review, and that sprint must count. Pinned in Task 2.
4. **Claude missing:** if `claude.js` failed to load, the Claude reward is never offered and nothing gets wrapped. Pinned in Task 2.
5. **A locked developer is sold during the lock:** the lock entry is dropped and `draw` doesn't crash. Pinned in Task 3.

### Task 2: Progress, claiming and real rewards

**Files:**
- Modify: `src/content/features/mailbox.js`
- Test: `tests/mailbox.test.js`

**Interfaces:**
- Consumes: `Mail`, `TEMPLATES`, `deliverMail` from Task 1.
- Produces:
  - `trackMail(game, eventName, data): void`. It calls each open mail's template handler for `eventName`, then caps progress: `progress = min(target, progress + inc)`.
  - `isDone(mail): boolean`
  - `claimMail(game, mailId): 'reward' | 'stolen' | 'malware' | 'compromised' | null`. It returns `null` if the mail is missing or not done, and removes the mail otherwise. Phishing goes to `applyPenalty` (Task 3; until then phishing claims return `'stolen'` via a stub).
  - Top-level `on(name, d => d.game.mailbox && trackMail(d.game, name, d))` for `dev:placed`, `dev:levelup`, `bug:killed`, `bug:leaked`, `wave:start`, `sprint:cleared`.
  - `wrapClaude()`, called from `init`. If `getPowerup('claude')` exists and isn't already wrapped, its `getCost` becomes `g => g.mailbox?.vouchers > 0 ? 0 : original(g)`.
  - Top-level `on('powerup:activated', ...)`: when the id is `claude` and `vouchers > 0`, it decrements `vouchers`.

**Handlers:**
- Hire: `dev:placed` with `data.dev.type === X` gives 1.
- Promote to Consultant: `dev:levelup` with `data.level >= 1` gives 1.
- Promote to Senior Consultant: `data.level === 2`.
- Squash: `bug:killed` with `data.bug.type === X` gives 1.
- `survive-sprints`: target 2, subject `Survive 2 more sprints`. `sprint:cleared` gives 1.
- `no-leak`:
  - The subject is `Clear a sprint without a single leak`.
  - `wave:start` sets `mail.armed = true` and `mail.leaked = false`, and gives 0.
  - `bug:leaked` sets `mail.leaked = true`.
  - `sprint:cleared` gives `mail.armed && !mail.leaked ? 1 : 0`.

**Reward:**
- Warrants: `addWarrants(game, amount)`, so it counts in `stats.warrantsEarned`.
- Claude: `vouchers++`.
- Either way, a banner with title `Reward claimed`, text `${from}: +${amount} Warrants` or `${from}: free Claude`, accent `#16A34A`, ttl 2.5.
- The Claude reward is only offered when `getPowerup('claude')` exists. A Claude mail shows its reward as "Free Claude".

- [ ] **Step 1: Write the failing tests**:
  - `hire-dotnet counts only dotnet placements`
  - `progress caps at target`
  - `promote-senior ignores level 1`
  - `squash-typo counts typo kills`
  - `claim before done returns null`
  - `claim pays Warrants and removes the mail`. Check `warrants` and `stats.warrantsEarned` both rise by the reward, and there's a `Reward claimed` banner.
  - `second claim of the same mail returns null` (Review Focus 2)
  - `survive-sprints completes after 2 sprint:cleared, including one that leads into a quarter review` (Review Focus 3). Emit `sprint:cleared` twice, setting `g.phase = 'review'` between them. The mail is done.
  - `no-leak fails when a bug leaks during the sprint`
  - `claude voucher makes Claude cost 0 and is spent on activation`. Register a stub `claude` power-up with `getCost: () => 150`, call `init`, set `vouchers = 1`. Then `powerupCost(g,'claude') === 0`. After `emit('powerup:activated', {game:g, id:'claude'})`, vouchers are 0 and the cost is 150 again.
  - `no claude reward without a claude power-up` (Review Focus 4). With no `claude` registered and every roll at 0, the reward kind is `warrants`.
  - `wrapClaude does not double-wrap across inits`. After two inits with a voucher, the cost is 0, and with no voucher it's 150.

### Task 3: Phishing penalties

**Files:**
- Modify: `src/content/features/mailbox.js`
- Test: `tests/mailbox.test.js`

**Interfaces:**
- Consumes: `claimMail` from Task 2.
- Produces:
  - `applyPenalty(game, mail): 'stolen' | 'malware' | 'compromised'`. The kind is picked with `game.random()` over the three kinds in that order. Compromised with no developers falls back to stolen.
  - `stealAmount(mail): number`. It returns `reward.amount`, or `CLAUDE_STEAL` for a Claude reward.
  - `malwareCount(game): number`, which is `Math.min(8, 3 + Math.floor(game.sprint / 3))`.
  - Top-level `on('wave:start', ...)`: spawns `pendingMalware` bugs and resets it to 0.
  - `draw(ctx, game)`:
    - a red tint over the map while `mailbox.flash > 0` (`rgba(220,38,38,·)`, fading)
    - for each live lock whose dev still exists, a grey veil and a padlock drawn with canvas shapes over that developer
  - `update` drops expired locks and locks whose dev is gone, and decays `flash`.

**Penalty behaviour:**
- **Stolen:** `warrants = Math.max(0, warrants - stealAmount(mail))`.
- **Malware:**
  - During the `wave` phase, `spawnBug(game, type, distance)` runs `malwareCount` times. The type is a random pick from `getBugs().filter(b => !b.boss)`, and the distance is spread 0 to 30 px.
  - In any other phase, it adds to `pendingMalware` instead.
- **Compromised:** picks a random `game.devs` entry, sets `dev.cooldown = LOCK_SECONDS`, and pushes `{ devId: dev.id, until: game.time + LOCK_SECONDS }`.
- **Every penalty:** sets `mailbox.flash = 0.4` and shows a banner with title `Phished` and accent `#DC2626`, ttl 3. The texts:
  - Stolen: `That wasn't ${from}. ${n} Warrants gone.`
  - Malware during a sprint: `The attachment was malware. ${n} bugs incoming.`
  - Malware queued: `The attachment was malware. ${n} bugs next sprint.`
  - Compromised: `A ${devName} developer gave away their password.`

  `devName` is `getDeveloper(dev.type).name`. Each text stays at most about 45 characters, because the banner is 320 px wide.

- [ ] **Step 1: Write the failing tests**:
  - `stolen subtracts the reward and floors at 0`
  - `stolen claude mail costs 100`
  - `malware spawns min(8, 3 + floor(sprint/3)) non-boss bugs during a sprint`. At `g.sprint = 6` that's 5 bugs, and at `g.sprint = 30` it's 8. Register a bug with `boss: true` and check it never spawns.
  - `malware outside a sprint is queued and spawns on wave:start`
  - `compromised locks one developer for 10 s`. Check `dev.cooldown === 10` and that the lock exists.
  - `compromised falls back to stolen with no developers`
  - `phishing claim shows a Phished banner and no reward`
  - `lock is dropped when its developer is sold` (Review Focus 5). Lock a dev, remove it from `g.devs`, run `update`, and `locks` is empty. Also call `draw` with a stub ctx whose methods are no-ops, and it doesn't throw.
  - `restart clears queued malware`. Covered by Task 1's init test; check that `pendingMalware` is in that deep-equal.

- [ ] **Step 2: Run `node --test tests/mailbox.test.js`.** Expected: the new tests FAIL.

- [ ] **Step 3: Implement** `applyPenalty`, `stealAmount`, `malwareCount`, the `wave:start` flush, and the `update`/`draw` additions. Replace the Task 2 stub.

- [ ] **Step 4: Run `node --test`.** Expected: all pass.

- [ ] **Step 5: Commit**: `git commit -am "feat: add phishing penalties"`.

### Task 4: Inbox card, panel, toast and sound

**Files:**
- Modify: `src/content/features/mailbox.js`
- Modify: `README.md`. Add one bullet under "How it plays" describing the inbox, in house style.

**Interfaces:**
- Consumes: `game.mailbox`, `claimMail`, `isDone`, and the `mail:received` bus event.
- Produces: DOM only. Nothing in this task runs when `typeof document === 'undefined'`.

**What to build:**
- **Styles:** inject one `<style id="mailbox-style">` the first time `init` runs in a browser, using the classes and look of `docs/mockups/mailbox.html`.
- **Inbox card:**
  - It's the `hudButtons` entry labelled `Inbox`. `onClick` toggles `mailbox.open` and marks all mails read when opening.
  - `resetUI` rebuilds the power-up bar, so on each `update` the code finds the `#powerups .pu.feature` whose `<b>` text is `Inbox`.
  - On that card it sets the `<small>` text to `${unread} new · ${mails.length}/4` and keeps one `.badge` span with the unread count (hidden at 0).
- **Panel:**
  - A `div.mb-inbox` inside `#stage`, on the **left** side (so it doesn't cover the bell card at the bottom right), shown when `mailbox.open`.
  - Each mail shows the sender, subject, reward (`+N W` or `Free Claude`), a progress bar with `progress/target`, and a `Claim` button when done.
  - Hidden while `game.phase === 'review'`.
  - Clicking Claim calls `claimMail`, then plays `'mail'` for a reward or `'phished'` for a penalty.
  - The footer reads `Next mail in ${ceil(timer)} s`, or `Inbox full · new mail paused` at 4.
  - The panel re-renders only when the mail list or a mail's progress changed, compared against a key string, so buttons stay clickable between frames.
- **Toast:**
  - On `mail:received`, unless `mailbox.open`, show a `div.mb-toast` at the top right of `#stage` with `New mail · ${from}`, the subject and the reward. It plays `'mail'`.
  - It's removed after 4 s of real time (`setTimeout`). Clicking it opens the inbox.
  - The toast and panel set `pointer-events` only on themselves, so the canvas underneath stays clickable.
- **Sounds:** `registerSound('mail', ...)` is a short two-note chime. `registerSound('phished', ...)` is a falling sawtooth. Both use the passed `tone`.
- **Restart:** `init` empties the panel, removes any toast and sets `open = false`. It doesn't add listeners.
- **Line height:** `#stage` has `line-height: 0`, so the panel and toast set `line-height: 1.3`.
